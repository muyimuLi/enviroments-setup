# PostgreSQL Docker 安装与 Spring Boot 对接指南

> 适用环境：Windows 10/11 + Docker Desktop + Spring Boot 3.x/4.x  
> 整理日期：2026-10-18

## 0. 先看本机现状

当前机器上已经有一个运行中的容器：

| 项目 | 值 |
|---|---|
| 容器名 | `pgvector` |
| 镜像 | `pgvector/pgvector:pg17` |
| PostgreSQL 版本 | 17.11 |
| 宿主机端口 | `5432` |
| 已有数据库 | `postgres`、`vectordb` |

这意味着：

1. **如果只是想要一个普通 PostgreSQL**，现有的 `pgvector` 容器本身就是 PostgreSQL，可以直接在里面建库建表，不必再启动第二个实例。
2. **如果想保持业务库和向量库隔离**，可以再启动一个独立容器，但宿主机端口要改成 `5433`，否则会报 `port is already allocated`。

本文的两个方案都会给出，按需选择。

## 一、在 Docker 里安装 PostgreSQL

### 1.1 前置检查

打开 PowerShell，确认 Docker 正常：

```powershell
docker version
docker compose version
```

确认端口占用情况：

```powershell
netstat -ano | findstr :5432
netstat -ano | findstr :5433
```

有输出说明端口被占用。也可以直接看容器：

```powershell
docker ps --format "table {{.Names}}\t{{.Image}}\t{{.Ports}}\t{{.Status}}"
```

### 1.2 方案 A：docker run（最快）

下面的命令启动一个独立的 PostgreSQL 17，宿主机端口用 `5433`：

```powershell
docker run -d --name postgres17 -e POSTGRES_USER=postgres -e POSTGRES_PASSWORD=postgres -e POSTGRES_DB=mydb -e TZ=Asia/Shanghai -p 5433:5432 -v postgres17_data:/var/lib/postgresql/data --restart unless-stopped postgres:17
```

参数说明：

| 参数 | 作用 |
|---|---|
| `-d` | 后台运行 |
| `--name postgres17` | 容器名，后续命令都用它 |
| `POSTGRES_USER` | 超级用户，默认是 `postgres` |
| `POSTGRES_PASSWORD` | 密码，**必填** |
| `POSTGRES_DB` | 初始化时自动创建的数据库 |
| `-p 5433:5432` | 宿主机 5433 映射到容器内 5432 |
| `-v postgres17_data:/var/lib/postgresql/data` | 命名卷持久化数据 |
| `--restart unless-stopped` | 开机/重启 Docker 后自动拉起 |

> **Windows PowerShell 注意**：不要照抄 Linux 教程里的 `\` 换行符，PowerShell 用的是反引号 `` ` ``，而且很容易复制出错。建议直接用上面的一行命令。

> **PostgreSQL 18 镜像的变化**：如果使用 `postgres:18` 或更高版本，官方镜像的数据目录改成了 `/var/lib/postgresql/18/docker`，推荐挂载点是 `/var/lib/postgresql` 而不是 `/var/lib/postgresql/data`。用 17 则按上面的写法即可。

带健康检查的完整写法：

```powershell
docker run -d --name postgres17 -e POSTGRES_USER=postgres -e POSTGRES_PASSWORD=postgres -e POSTGRES_DB=mydb -e TZ=Asia/Shanghai -p 5433:5432 -v postgres17_data:/var/lib/postgresql/data --health-cmd "pg_isready -U postgres -d mydb" --health-interval 10s --health-timeout 5s --health-retries 5 --restart unless-stopped postgres:17
```

### 1.3 方案 B：docker compose（推荐）

新建目录，例如 `C:\docker\postgres`，在里面创建 `compose.yaml`：

```yaml
services:
  postgres:
    image: postgres:17
    container_name: postgres17
    restart: unless-stopped
    environment:
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: postgres
      POSTGRES_DB: mydb
      TZ: Asia/Shanghai
      PGTZ: Asia/Shanghai
    ports:
      - "5433:5432"
    volumes:
      - postgres17_data:/var/lib/postgresql/data
      - ./init:/docker-entrypoint-initdb.d:ro
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U postgres -d mydb"]
      interval: 10s
      timeout: 5s
      retries: 5

volumes:
  postgres17_data:
```

启动：

```powershell
cd C:\docker\postgres
docker compose up -d
```

查看状态：

```powershell
docker compose ps
docker compose logs -f postgres
```

停止但保留数据：

```powershell
docker compose stop
```

停止并删除容器（**命名卷还在，数据不丢**）：

```powershell
docker compose down
```

连数据卷一起删（**数据会永久丢失**，谨慎执行）：

```powershell
docker compose down -v
```

### 1.4 初始化 SQL 脚本

把 `.sql` 文件放到 `./init` 目录，容器**第一次**初始化时会按文件名顺序自动执行：

```text
C:\docker\postgres\
├─ compose.yaml
└─ init\
   ├─ 01-create-schema.sql
   └─ 02-create-table.sql
```

示例 `01-create-schema.sql`：

```sql
CREATE SCHEMA IF NOT EXISTS app;

CREATE TABLE IF NOT EXISTS app.app_user (
    id          BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    username    VARCHAR(64)  NOT NULL UNIQUE,
    email       VARCHAR(128),
    status      SMALLINT     NOT NULL DEFAULT 1,
    created_at  TIMESTAMPTZ  NOT NULL DEFAULT now()
);
```

注意：这些脚本**只在数据目录为空时执行一次**。如果卷里已经有数据，再改脚本不会生效，需要手动执行或使用 Flyway/Liquibase 做版本化迁移。

### 1.5 验证是否安装成功

```powershell
docker ps
docker logs postgres17
```

进入容器执行 psql：

```powershell
docker exec -it postgres17 psql -U postgres -d mydb
```

进入后执行：

```sql
SELECT version();
SELECT current_database(), current_user, now();
\l
\q
```

能正常返回版本号和数据库列表，就说明安装成功。

### 1.6 数据持久化说明

| 方式 | 写法 | 特点 |
|---|---|---|
| 命名卷 | `-v postgres17_data:/var/lib/postgresql/data` | 推荐，Docker 管理，性能好 |
| 绑定目录 | `-v C:\docker\pgdata:/var/lib/postgresql/data` | 数据文件直观可见，但 Windows 下权限和性能问题较多 |

不要把数据目录挂到 NTFS 的普通目录后再频繁读写，WSL2 下跨文件系统 I/O 会明显变慢。需要备份时用 `pg_dump`，不要直接复制正在运行的数据文件。

### 1.7 常见安装问题

| 现象 | 原因 | 解决 |
|---|---|---|
| `port is already allocated` | 5432 已被 pgvector 占用 | 改成 `-p 5433:5432` |
| `database files are incompatible with server` | 旧数据卷是另一个大版本创建的 | 换新卷，或用 `pg_upgrade` 迁移 |
| 改了 `POSTGRES_PASSWORD` 但不生效 | 环境变量只在数据目录为空时初始化 | 进库执行 `ALTER USER postgres WITH PASSWORD '新密码';` |
| 初始化 SQL 没执行 | 数据目录非空 | 手动执行，或删卷重建（会丢数据） |
| 宿主机连不上 | 端口没映射 / 容器没起来 | `docker ps`、`docker logs`、检查 `-p` |
| 中文乱码 | 数据库编码不是 UTF8 | 建库时指定 `ENCODING 'UTF8' TEMPLATE template0` |

## 二、Spring Boot 对接 PostgreSQL

### 2.1 加依赖

Maven（`pom.xml`）：

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-data-jpa</artifactId>
</dependency>

<dependency>
    <groupId>org.postgresql</groupId>
    <artifactId>postgresql</artifactId>
    <scope>runtime</scope>
</dependency>
```

如果只想用 `JdbcTemplate`，把第一个依赖换成：

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-jdbc</artifactId>
</dependency>
```

Gradle：

```groovy
implementation 'org.springframework.boot:spring-boot-starter-data-jpa'
runtimeOnly 'org.postgresql:postgresql'
```

`org.postgresql:postgresql` 的版本由 Spring Boot 的 BOM 管理，通常不需要手写版本号。

### 2.2 application.yaml 配置

```yaml
spring:
  datasource:
    url: jdbc:postgresql://localhost:5433/mydb
    username: postgres
    password: postgres
    driver-class-name: org.postgresql.Driver
    hikari:
      maximum-pool-size: 10
      minimum-idle: 2
      connection-timeout: 30000
      idle-timeout: 600000
      max-lifetime: 1800000

  jpa:
    open-in-view: false
    hibernate:
      ddl-auto: validate
    properties:
      hibernate:
        jdbc:
          time_zone: Asia/Shanghai
    show-sql: true
```

说明：

- 端口要和 `docker run -p` 的**宿主机端口**一致。本文新实例是 `5433`；如果直接用现有的 pgvector 容器，则是 `5432`。
- `ddl-auto` 建议：开发期可用 `update`，生产环境用 `validate`，表结构交给 Flyway/Liquibase 管理。
- `open-in-view: false` 可以避免懒加载在视图层偷偷查库。
- PostgreSQL 不需要手动指定 `hibernate.dialect`，Hibernate 会自动识别。

用环境变量覆盖更安全：

```yaml
spring:
  datasource:
    url: ${DB_URL:jdbc:postgresql://localhost:5433/mydb}
    username: ${DB_USERNAME:postgres}
    password: ${DB_PASSWORD:postgres}
```

### 2.3 建表 SQL

```sql
CREATE TABLE IF NOT EXISTS app_user (
    id          BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    username    VARCHAR(64)  NOT NULL UNIQUE,
    email       VARCHAR(128),
    status      SMALLINT     NOT NULL DEFAULT 1,
    profile     JSONB,
    created_at  TIMESTAMPTZ  NOT NULL DEFAULT now(),
    updated_at  TIMESTAMPTZ  NOT NULL DEFAULT now()
);

CREATE INDEX IF NOT EXISTS idx_app_user_created_at
    ON app_user (created_at DESC);
```

### 2.4 实体类

```java
package com.example.demo.user;

import jakarta.persistence.*;
import org.hibernate.annotations.JdbcTypeCode;
import org.hibernate.type.SqlTypes;

import java.time.OffsetDateTime;

@Entity
@Table(name = "app_user")
public class AppUser {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(nullable = false, unique = true, length = 64)
    private String username;

    @Column(length = 128)
    private String email;

    @Column(nullable = false)
    private Short status = 1;

    @JdbcTypeCode(SqlTypes.JSON)
    @Column(columnDefinition = "jsonb")
    private String profile;

    @Column(name = "created_at", nullable = false, insertable = false, updatable = false)
    private OffsetDateTime createdAt;

    @Column(name = "updated_at", nullable = false, insertable = false, updatable = false)
    private OffsetDateTime updatedAt;

    // getter / setter 省略
}
```

要点：

- `BIGINT IDENTITY` 对应 `GenerationType.IDENTITY`。
- `TIMESTAMPTZ` 用 `OffsetDateTime` 或 `Instant`，不要用没有时区含义的 `LocalDateTime`。
- `JSONB` 在 Hibernate 6 中可用 `@JdbcTypeCode(SqlTypes.JSON)`；用原生 SQL 写入时可能需要 `?::jsonb` 强转。

### 2.5 Repository

```java
package com.example.demo.user;

import org.springframework.data.jpa.repository.JpaRepository;

import java.util.Optional;

public interface AppUserRepository extends JpaRepository<AppUser, Long> {

    Optional<AppUser> findByUsername(String username);

    boolean existsByEmail(String email);
}
```

### 2.6 Service 与事务

```java
@Service
public class AppUserService {

    private final AppUserRepository repository;

    public AppUserService(AppUserRepository repository) {
        this.repository = repository;
    }

    @Transactional
    public AppUser create(String username, String email) {
        AppUser user = new AppUser();
        user.setUsername(username);
        user.setEmail(email);
        return repository.save(user);
    }

    @Transactional(readOnly = true)
    public AppUser getByUsername(String username) {
        return repository.findByUsername(username)
                .orElseThrow(() -> new IllegalArgumentException("用户不存在: " + username));
    }
}
```

### 2.7 用 JdbcTemplate 的写法

```java
@Repository
public class AppUserJdbcRepository {

    private final JdbcTemplate jdbcTemplate;

    public AppUserJdbcRepository(JdbcTemplate jdbcTemplate) {
        this.jdbcTemplate = jdbcTemplate;
    }

    public List<Map<String, Object>> findAll() {
        return jdbcTemplate.queryForList(
                "SELECT id, username, email, created_at FROM app_user ORDER BY id DESC");
    }

    public Long insert(String username, String email) {
        return jdbcTemplate.queryForObject(
                "INSERT INTO app_user(username, email) VALUES (?, ?) RETURNING id",
                Long.class, username, email);
    }
}
```

### 2.8 验证连接

启动应用后看日志，出现 HikariPool 启动成功且没有异常即可。也可以写一个测试：

```java
@SpringBootTest
class PostgresConnectionTest {

    @Autowired
    private JdbcTemplate jdbcTemplate;

    @Test
    void connectionWorks() {
        String version = jdbcTemplate.queryForObject("SELECT version()", String.class);
        assertThat(version).contains("PostgreSQL");
    }
}
```

### 2.9 Spring Boot 常见报错

| 报错 | 原因 | 解决 |
|---|---|---|
| `Connection refused` | 端口不对 / 容器没启动 | 核对 `-p` 映射，`docker ps` |
| `password authentication failed` | 密码错误或改过环境变量但未生效 | 用 `ALTER USER` 改密码 |
| `database "xxx" does not exist` | 库名写错或没创建 | `CREATE DATABASE xxx;` |
| `relation "xxx" does not exist` | 表不存在 / schema 不对 | 检查 `search_path`，执行建表 SQL |
| `Schema-validation: missing table` | `ddl-auto: validate` 且表没建 | 建表或用 Flyway |
| `column is of type jsonb but expression is of type character varying` | JSONB 写入类型不匹配 | SQL 里写 `?::jsonb`，或实体加 `@JdbcTypeCode` |
| `FATAL: no pg_hba.conf entry` | 认证规则不允许该来源 | 检查容器内 `pg_hba.conf` |
| 时间差 8 小时 | 用了 `TIMESTAMP` + `LocalDateTime` | 改用 `TIMESTAMPTZ` + `OffsetDateTime/Instant` |

### 2.10 同时使用 MySQL 和 PostgreSQL（可选）

一个 Spring Boot 应用默认只有一个 `spring.datasource`。如果 MySQL 和 PostgreSQL 都要用，需要多数据源：

1. 主数据源用 `spring.datasource`，另一个用自定义前缀，例如 `pg.datasource`。
2. 为第二个库单独创建 `DataSource`、`JdbcTemplate`，并用 `@Qualifier` 区分。
3. 主数据源加 `@Primary`。
4. 使用 JPA 时，还要分别配置 `EntityManagerFactory` 和 `TransactionManager`。
5. 如果用了 Spring AI 的 pgvector 自动配置，要排除 `PgVectorStoreAutoConfiguration`，手动构建 `PgVectorStore`，否则它会抢数据源。
6. 多数据源下 `spring.sql.init.mode` 要谨慎，设为 `always` 可能把 PostgreSQL 的初始化脚本跑到 MySQL 上。

## 三、PostgreSQL 常用运维与库表命令

### 3.1 进入容器和 psql

```powershell
# 进入默认库
docker exec -it postgres17 psql -U postgres

# 进入指定库
docker exec -it postgres17 psql -U postgres -d mydb

# 直接执行一条 SQL 后退出
docker exec -it postgres17 psql -U postgres -d mydb -c "SELECT now();"

# 进入容器 shell
docker exec -it postgres17 bash
```

> psql 里每条 SQL 都要以分号 `;` 结尾。只敲回车不会执行，会一直显示 `mydb=#`，看起来像“没有响应”。

### 3.2 psql 元命令（反斜杠命令）

| 命令 | 作用 |
|---|---|
| `\l` | 列出所有数据库 |
| `\c mydb` | 切换到 mydb |
| `\conninfo` | 查看当前连接信息 |
| `\dt` | 列出当前 schema 的表 |
| `\dt *.*` | 列出所有 schema 的表 |
| `\dt+` | 列表并显示大小 |
| `\d app_user` | 查看表结构、索引、约束 |
| `\d+ app_user` | 更详细，含存储和注释 |
| `\dn` | 列出 schema |
| `\du` | 列出角色/用户 |
| `\df` | 列出函数 |
| `\dv` | 列出视图 |
| `\di` | 列出索引 |
| `\dp` | 查看权限 |
| `\x` | 切换横向/纵向显示，宽表很有用 |
| `\timing` | 开关 SQL 执行耗时 |
| `\watch 5` | 每 5 秒重复执行上一条 SQL |
| `\e` | 用编辑器写多行 SQL |
| `\i /path/file.sql` | 执行 SQL 文件 |
| `\copy` | 客户端导入导出 CSV |
| `\q` | 退出 |
| `\?` | 查看所有元命令 |

### 3.3 数据库操作

```sql
-- 查看版本和当前连接
SELECT version();
SELECT current_database(), current_user, now();

-- 创建数据库
CREATE DATABASE mydb
    WITH ENCODING 'UTF8'
    TEMPLATE template0;

-- 指定所有者
CREATE DATABASE mydb OWNER appuser;

-- 修改数据库
ALTER DATABASE mydb RENAME TO mydb2;
ALTER DATABASE mydb OWNER TO appuser;

-- 删除数据库（不能删除当前正在连接的库）
DROP DATABASE IF EXISTS mydb;

-- 查看所有数据库及大小
SELECT datname,
       pg_size_pretty(pg_database_size(datname)) AS size
FROM pg_database
ORDER BY pg_database_size(datname) DESC;
```

删除库之前先断开连接：

```sql
SELECT pg_terminate_backend(pid)
FROM pg_stat_activity
WHERE datname = 'mydb'
  AND pid <> pg_backend_pid();

DROP DATABASE mydb;
```

### 3.4 用户与权限

```sql
-- 创建可登录用户
CREATE ROLE appuser LOGIN PASSWORD 'StrongPass123';

-- 允许连接数据库
GRANT CONNECT ON DATABASE mydb TO appuser;

-- 进入目标库后，授予 schema 权限
GRANT USAGE ON SCHEMA public TO appuser;

-- 授予现有表权限
GRANT SELECT, INSERT, UPDATE, DELETE
ON ALL TABLES IN SCHEMA public TO appuser;

-- 授予序列权限（自增主键需要）
GRANT USAGE, SELECT
ON ALL SEQUENCES IN SCHEMA public TO appuser;

-- 以后新建的表也自动授权
ALTER DEFAULT PRIVILEGES IN SCHEMA public
GRANT SELECT, INSERT, UPDATE, DELETE ON TABLES TO appuser;

ALTER DEFAULT PRIVILEGES IN SCHEMA public
GRANT USAGE, SELECT ON SEQUENCES TO appuser;

-- 修改密码
ALTER USER appuser WITH PASSWORD 'NewPass456';

-- 查看角色
\du

-- 回收权限
REVOKE DELETE ON ALL TABLES IN SCHEMA public FROM appuser;
```

PostgreSQL 15 起，普通用户默认不能在 `public` schema 建表。需要可写 schema 时，建议单独建：

```sql
CREATE SCHEMA app AUTHORIZATION appuser;
GRANT USAGE, CREATE ON SCHEMA app TO appuser;
```

### 3.5 表操作

创建表：

```sql
CREATE TABLE public.app_user (
    id          BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    username    VARCHAR(64)  NOT NULL UNIQUE,
    email       VARCHAR(128),
    status      SMALLINT     NOT NULL DEFAULT 1,
    profile     JSONB,
    tags        TEXT[],
    created_at  TIMESTAMPTZ  NOT NULL DEFAULT now(),
    updated_at  TIMESTAMPTZ  NOT NULL DEFAULT now()
);

COMMENT ON TABLE public.app_user IS '应用用户表';
COMMENT ON COLUMN public.app_user.username IS '登录名';
```

修改表：

```sql
-- 加列
ALTER TABLE app_user ADD COLUMN nickname VARCHAR(64);

-- 改列名
ALTER TABLE app_user RENAME COLUMN nickname TO display_name;

-- 改类型
ALTER TABLE app_user ALTER COLUMN email TYPE VARCHAR(255);

-- 改默认值
ALTER TABLE app_user ALTER COLUMN status SET DEFAULT 0;

-- 加约束
ALTER TABLE app_user
    ADD CONSTRAINT ck_app_user_status CHECK (status IN (0, 1));

-- 删约束
ALTER TABLE app_user DROP CONSTRAINT ck_app_user_status;

-- 删列
ALTER TABLE app_user DROP COLUMN display_name;

-- 改表名
ALTER TABLE app_user RENAME TO sys_user;

-- 清空表（保留结构）
TRUNCATE TABLE app_user RESTART IDENTITY;

-- 清空并级联
TRUNCATE TABLE app_user RESTART IDENTITY CASCADE;

-- 删表
DROP TABLE IF EXISTS app_user;
```

查看表：

```sql
\d app_user
\d+ app_user
\dt
\dt+

-- 查列信息
SELECT column_name, data_type, is_nullable, column_default
FROM information_schema.columns
WHERE table_schema = 'public'
  AND table_name = 'app_user'
ORDER BY ordinal_position;

-- 查所有表及大小
SELECT relname AS table_name,
       n_live_tup AS rows,
       pg_size_pretty(pg_total_relation_size(relid)) AS total_size
FROM pg_stat_user_tables
ORDER BY pg_total_relation_size(relid) DESC;
```

### 3.6 索引

```sql
-- 普通 B-Tree 索引
CREATE INDEX idx_app_user_created_at
    ON app_user (created_at DESC);

-- 唯一索引
CREATE UNIQUE INDEX uk_app_user_email
    ON app_user (lower(email))
    WHERE email IS NOT NULL;

-- JSONB 字段的 GIN 索引
CREATE INDEX idx_app_user_profile_gin
    ON app_user USING GIN (profile);

-- 查看索引
\di
SELECT indexname, indexdef
FROM pg_indexes
WHERE tablename = 'app_user';

-- 查看索引使用次数
SELECT indexrelname, idx_scan, idx_tup_read, idx_tup_fetch
FROM pg_stat_user_indexes
WHERE relname = 'app_user'
ORDER BY idx_scan;

-- 在线建索引（不阻塞写入，不能放在事务块里）
CREATE INDEX CONCURRENTLY idx_app_user_status
    ON app_user (status);

-- 重建索引
REINDEX INDEX CONCURRENTLY idx_app_user_created_at;

-- 删除索引
DROP INDEX IF EXISTS idx_app_user_status;
```

### 3.7 数据增删改查

```sql
-- 插入并返回主键
INSERT INTO app_user (username, email)
VALUES ('alice', 'alice@example.com')
RETURNING id, created_at;

-- 批量插入
INSERT INTO app_user (username, email) VALUES
('bob', 'bob@example.com'),
('carol', 'carol@example.com');

-- Upsert：存在则更新
INSERT INTO app_user (username, email)
VALUES ('alice', 'new@example.com')
ON CONFLICT (username)
DO UPDATE SET email = EXCLUDED.email,
              updated_at = now()
RETURNING *;

-- 查询
SELECT * FROM app_user WHERE status = 1 ORDER BY id DESC;

-- 分页
SELECT * FROM app_user ORDER BY id LIMIT 20 OFFSET 0;

-- 模糊查询
SELECT * FROM app_user WHERE username ILIKE '%ali%';

-- JSONB 查询
SELECT * FROM app_user WHERE profile -> 'city' = '"Shanghai"';
SELECT * FROM app_user WHERE profile @> '{"level": 3}';

-- 数组包含
SELECT * FROM app_user WHERE tags @> ARRAY['vip'];

-- 更新
UPDATE app_user
SET email = 'x@example.com',
    updated_at = now()
WHERE id = 1
RETURNING *;

-- 删除
DELETE FROM app_user WHERE id = 1 RETURNING *;

-- 统计
SELECT count(*) FROM app_user;
```

事务：

```sql
BEGIN;
UPDATE app_user SET status = 0 WHERE id = 1;
UPDATE app_user SET status = 1 WHERE id = 2;
COMMIT;    -- 出错时用 ROLLBACK;
```

执行计划：

```sql
EXPLAIN SELECT * FROM app_user WHERE username = 'alice';
EXPLAIN (ANALYZE, BUFFERS)
SELECT * FROM app_user WHERE created_at > now() - interval '7 days';
```

### 3.8 连接与性能排查

查看当前连接：

```sql
SELECT pid,
       usename,
       datname,
       state,
       wait_event_type,
       wait_event,
       now() - query_start AS duration,
       left(query, 200) AS query
FROM pg_stat_activity
WHERE state <> 'idle'
ORDER BY duration DESC;
```

查看连接数上限和使用量：

```sql
SHOW max_connections;
SELECT count(*) AS current_connections FROM pg_stat_activity;
SELECT usename, count(*) FROM pg_stat_activity GROUP BY usename;
```

查找阻塞：

```sql
SELECT blocked.pid        AS blocked_pid,
       blocked.usename    AS blocked_user,
       blocking.pid       AS blocking_pid,
       blocking.usename   AS blocking_user,
       blocked.query      AS blocked_query,
       blocking.query     AS blocking_query
FROM pg_stat_activity blocked
JOIN pg_stat_activity blocking
  ON blocking.pid = ANY(pg_blocking_pids(blocked.pid))
WHERE blocked.pid <> pg_backend_pid();
```

取消或终止会话：

```sql
-- 温和取消当前查询
SELECT pg_cancel_backend(12345);

-- 强制断开连接
SELECT pg_terminate_backend(12345);
```

查看未授予的锁：

```sql
SELECT locktype, relation::regclass AS relation, mode, granted, pid
FROM pg_locks
WHERE NOT granted;
```

查看表膨胀和统计信息：

```sql
SELECT relname,
       n_live_tup,
       n_dead_tup,
       last_vacuum,
       last_autovacuum,
       last_analyze,
       last_autoanalyze
FROM pg_stat_user_tables
ORDER BY n_dead_tup DESC;
```

执行清理：

```sql
-- 日常维护，锁级别低
VACUUM (ANALYZE) app_user;

-- 只更新统计信息
ANALYZE app_user;

-- 回收空间，会锁表，生产慎用
VACUUM FULL app_user;
```

### 3.9 配置查看与修改

```sql
-- 查看配置
SHOW shared_buffers;
SHOW work_mem;
SHOW timezone;
SHOW data_directory;
SHOW config_file;
SHOW hba_file;

-- 查看某个参数
SELECT current_setting('max_connections');

-- 会话级临时修改
SET work_mem = '32MB';

-- 全局修改（写入 postgresql.auto.conf）
ALTER SYSTEM SET work_mem = '16MB';
SELECT pg_reload_conf();

-- 需要重启才生效的参数
ALTER SYSTEM SET max_connections = 200;
-- 然后 docker restart postgres17
```

内存参数建议（仅作起点，按机器规格调整）：

| 参数 | 建议 |
|---|---|
| `shared_buffers` | 物理内存的 25% 左右 |
| `work_mem` | 从 `4MB`~`16MB` 起，按并发和排序需求调 |
| `maintenance_work_mem` | `256MB`~`1GB` |
| `effective_cache_size` | 物理内存的 50%~75% |

### 3.10 备份与恢复

逻辑备份（推荐自定义格式，压缩且可选择性恢复）：

```powershell
# 在容器内生成备份文件
docker exec -t postgres17 pg_dump -U postgres -d mydb -Fc -f /tmp/mydb.dump

# 复制到 Windows
docker cp postgres17:/tmp/mydb.dump C:\backup\mydb.dump
```

恢复：

```powershell
docker cp C:\backup\mydb.dump postgres17:/tmp/mydb.dump
docker exec -t postgres17 pg_restore -U postgres -d mydb --clean --if-exists /tmp/mydb.dump
```

纯 SQL 备份：

```powershell
docker exec -t postgres17 pg_dump -U postgres -d mydb -f /tmp/mydb.sql
docker cp postgres17:/tmp/mydb.sql C:\backup\mydb.sql
```

恢复纯 SQL：

```powershell
docker cp C:\backup\mydb.sql postgres17:/tmp/mydb.sql
docker exec -it postgres17 psql -U postgres -d mydb -f /tmp/mydb.sql
```

> 不建议在 PowerShell 里用 `docker exec ... pg_dump > mydb.sql`。Windows PowerShell 的重定向可能写出 UTF-16 编码，恢复时会报错。用 `-f` 在容器内写文件，再 `docker cp` 出来最稳。

备份所有数据库和角色：

```powershell
docker exec -t postgres17 pg_dumpall -U postgres -f /tmp/all.sql
docker cp postgres17:/tmp/all.sql C:\backup\all.sql
```

只备份表结构：

```powershell
docker exec -t postgres17 pg_dump -U postgres -d mydb -s -f /tmp/schema.sql
```

只备份某张表：

```powershell
docker exec -t postgres17 pg_dump -U postgres -d mydb -t app_user -f /tmp/app_user.sql
```

### 3.11 迁移到新容器

```powershell
# 1. 旧库导出
docker exec -t pgvector pg_dump -U postgres -d vectordb -Fc -f /tmp/vectordb.dump
docker cp pgvector:/tmp/vectordb.dump C:\backup\vectordb.dump

# 2. 新容器建空库
docker exec -it postgres17 psql -U postgres -c "CREATE DATABASE vectordb;"

# 3. 导入
docker cp C:\backup\vectordb.dump postgres17:/tmp/vectordb.dump
docker exec -t postgres17 pg_restore -U postgres -d vectordb --no-owner /tmp/vectordb.dump
```

如果原库用了 pgvector 扩展，新镜像也必须是 `pgvector/pgvector:pg17`，普通 `postgres:17` 镜像没有这个扩展。

## 四、pgvector 补充（当前项目会用到）

现有的 `pgvector` 容器本身就是一个 PostgreSQL 17，可以直接使用：

```powershell
docker exec -it pgvector psql -U postgres -d vectordb
```

确认扩展：

```sql
CREATE EXTENSION IF NOT EXISTS vector;
SELECT extname, extversion FROM pg_extension WHERE extname = 'vector';
```

建向量表：

```sql
CREATE TABLE IF NOT EXISTS vector_store (
    id        UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    content   TEXT,
    metadata  JSONB,
    embedding VECTOR(1024)
);

CREATE INDEX IF NOT EXISTS idx_vector_store_embedding
    ON vector_store USING HNSW (embedding vector_cosine_ops);
```

Spring AI 配置片段：

```yaml
spring:
  ai:
    vectorstore:
      pgvector:
        index-type: HNSW
        distance-type: COSINE_DISTANCE
        dimensions: 1024
        initialize-schema: false
        schema-validation: true
```

`dimensions` 必须和嵌入模型输出维度一致，例如千问 `text-embedding-v4` 常用 1024 维。维度不一致会在写入或查询时报错。

## 五、最小验收清单

按顺序检查，全部通过就说明环境没问题：

```powershell
# 1. 容器在运行
docker ps --filter "name=postgres17"

# 2. 日志无报错
docker logs --tail 50 postgres17

# 3. 能进 psql
docker exec -it postgres17 psql -U postgres -d mydb -c "SELECT version();"

# 4. 宿主机端口可连
Test-NetConnection localhost -Port 5433

# 5. 建表成功
docker exec -it postgres17 psql -U postgres -d mydb -c "\dt"
```

Spring Boot 侧：

1. `pom.xml` 有 `spring-boot-starter-data-jpa` 和 `postgresql`。
2. `application.yaml` 的 URL 端口是 `5433`（或现有容器的 `5432`）。
3. 启动日志出现 `HikariPool-1 - Start completed`。
4. 调用一个查询接口能返回数据。

## 七、一句话总结

Docker 里装 PostgreSQL 只需一个 `docker run` 或一份 `compose.yaml`；Spring Boot 侧只要 JDBC URL、用户名、密码和驱动依赖；日常运维的核心是 `psql` 元命令、权限管理、索引与 `VACUUM`、以及用 `pg_dump/pg_restore` 做备份恢复。
